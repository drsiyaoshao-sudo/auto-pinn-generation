# Dispatch Model Fine-Tuning

Fine-tunes Qwen2.5-0.5B to parse engineering language into structured JSON args
for the GaitSense local dispatch agents. Replaces the zero-shot 0.5B inference path
with a domain-adapted model that understands IMU terms, profile names, run IDs, and
engineering shorthand.

---

## 0. Linux GPU Setup

**Target: Ubuntu 22.04 + RTX 2080 Ti (11 GB VRAM, Turing sm_75)**

VRAM budget for Qwen2.5-0.5B + LoRA + 4-bit base: ~3 GB active, ~5 GB peak.
The 2080 Ti has 11 GB — comfortable headroom for batch size 16.

Two Turing-specific notes:
- Use `--fp16` not `--bf16`. bfloat16 requires Ampere (sm_80+). bf16 on Turing silently
  falls back to fp32 and doubles VRAM usage.
- Pin bitsandbytes to 0.43.3 — earlier versions had sm_75 4-bit kernel bugs.

## 2. Fine-Tuning

### Register dataset with LLaMA-Factory

```bash
cd ~/auto-pinn-generation

# Copy JSONL to LLaMA-Factory's data directory
cp hybrid/training/data/dispatch_pairs.jsonl \
   $(python -c "import llamafactory; import os; print(os.path.dirname(llamafactory.__file__))")/data/dispatch_pairs.jsonl

# Add entry to dataset_info.json in that same data/ directory:
# "gaitsense_dispatch": {
#   "file_name": "dispatch_pairs.jsonl",
#   "formatting": "sharegpt",
#   "columns": {"messages": "messages"}
# }
```

### Train

```bash
llamafactory-cli train \
  --model_name_or_path Qwen/Qwen2.5-0.5B-Instruct \
  --dataset gaitsense_dispatch \
  --template qwen \
  --finetuning_type lora \
  --lora_rank 16 \
  --lora_alpha 32 \
  --lora_target q_proj,v_proj \
  --num_train_epochs 5 \
  --per_device_train_batch_size 16 \
  --gradient_accumulation_steps 2 \
  --learning_rate 2e-4 \
  --lr_scheduler_type cosine \
  --warmup_ratio 0.1 \
  --fp16 \
  --output_dir hybrid/training/checkpoints/dispatch_lora \
  --save_steps 50 \
  --logging_steps 10 \
  --overwrite_output_dir
```

Expected training time on common GPUs:

| GPU | VRAM | Batch size | Time (5 epochs, 1,360 ex) |
|-----|------|-----------|--------------------------|
| RTX 2080 Ti | 11 GB | 16 | ~4 min |
| RTX 3090 | 24 GB | 32 | ~2 min |
| RTX 4090 | 24 GB | 32 | ~90 sec |

### Merge LoRA adapters and export

```bash
# Merge adapter weights into the base model
llamafactory-cli export \
  --model_name_or_path Qwen/Qwen2.5-0.5B-Instruct \
  --adapter_name_or_path hybrid/training/checkpoints/dispatch_lora \
  --export_dir hybrid/training/checkpoints/dispatch_merged \
  --export_size 1

# Convert merged model to GGUF Q4_K_M for Ollama
python llama.cpp/convert_hf_to_gguf.py \
  hybrid/training/checkpoints/dispatch_merged \
  --outtype q4_k_m \
  --outfile hybrid/training/checkpoints/gaitsense_dispatch_q4.gguf

# Check GGUF size — should be ~350 MB
ls -lh hybrid/training/checkpoints/gaitsense_dispatch_q4.gguf
```

## 3. Deploy to Ollama

```bash
# Create Modelfile — temperature 0 for deterministic JSON extraction
cat > hybrid/training/Modelfile << 'MODELEOF'
FROM hybrid/training/checkpoints/gaitsense_dispatch_q4.gguf
PARAMETER temperature 0.0
PARAMETER top_p 1.0
PARAMETER repeat_penalty 1.0
MODELEOF

# Register with Ollama
ollama create gaitsense-dispatch -f hybrid/training/Modelfile

# Smoke test
ollama run gaitsense-dispatch "plot stairs pathological"
# Expected: {"profile": "stairs", "mode": "pathological"}

ollama run gaitsense-dispatch "show loss for v21_2k"
# Expected: {"run_id": "v21_2k"}

ollama run gaitsense-dispatch "compare good v1 vs untrained"
# Expected: {"good_run_id": "v1", "bad_run_id": "random"}
```

### Switch all dispatch agents to the fine-tuned model

```bash
# One env var — no code changes, LocalLLM reads OLLAMA_MODEL
export OLLAMA_MODEL=gaitsense-dispatch

# Or add to .env for persistence:
echo "OLLAMA_MODEL=gaitsense-dispatch" >> .env

# Test
python hybrid/local_agents/run_plotter.py "gy az check bad wear profile"
/hybrid-demo
```

## 4. Inference hardware targets

| Device | VRAM / RAM | Quantisation | Tok/s (decode) |
|--------|-----------|-------------|----------------|
| RTX 4090 (training box) | 24 GB | Q4_K_M | ~400 |
| RTX 2080 Ti | 11 GB | Q4_K_M | ~150 |
| M1 MacBook (8 GB) | 8 GB unified | Q4_K_M | ~50 |
| Raspberry Pi 5 (8 GB) | 8 GB | Q4_K_M | ~8 |
| nRF9160 (future) | 1 MB | requires further distillation | TBD |

The dispatch task is a single short completion (20–50 tokens output). Even at 8 tok/s on RPi5,
latency is under 1 second — acceptable for the parse-only dispatch path.
